# 2026-07-13 Notes

## TUI harness human-loop

Implemented elegant TUI compatibility for Pi/Codex-style harness interaction
(`docs/plans/2026-07-13-hlp-tui-harness-human-loop.md`).

### Changes

- `loops/tui/app.py`: Codex wires `CodexHarnessAdapter`; Pi keeps first-class
  CLI defaults; shared timeout/progress for live waits.
- `loops/tui/controller.py`: after prompt start/amend and after checkpoint
  resolve, auto-call `project_harness_events` when the adapter can observe/peek,
  then append a compact human-loop summary to output + transcript.
- `loops/tui/render.py`: `render_human_loop` for checkpoint/artifact/inbox hints.
- Tests: offline injected Codex + Pi harness runners through real controller
  (`prompt → project → /approve → artifact → /review`).

### Verification

- `uv run pytest tests/test_hlp_tui.py -q` → all passed
- Entry help lists `codex`/`fake`/`pi` and `--timeout`

### Agent reply surface fix

Live Pi returned JSON `summary` but TUI only printed `started task …` because
there were no projectable human events. Added `render_agent_reply` and post-
delegate/resume attachment of adapter `process_results` summary/status so
chat-style harness replies are visible.

### Chat mode prompt

TUI live harnesses now use `prompt_mode="chat"`:

- `chat_mode_prompt` / `prompt_for_adapter_operation` in
  `loops/hlp/adapters/process.py`
- Delegate prompts put the user message first; still require
  `correlation_id` / `run_id` / `summary` JSON (+ optional human events)
- Protocol mode remains default for non-TUI adapters and offline contract demos
- block/resume/cancel stay protocol-shaped even when `prompt_mode=chat`
- Follow-up TUI lines use `task.amend` → adapter `steer` with **chat** prompt
  and refresh `process_results` so the second reply is not a stale first-turn
  summary

### Harness streaming in TUI

- `run_prompt_process_streaming` + `format_harness_stream_line` map Pi/Codex
  JSONL (status, text_delta; suppress thinking_delta noise) to `StreamChunk`
- TUI `build_client` installs `make_streaming_prompt_runner` so live turns print
  `⋯ agent start` / live `⋯ agent: …` while waiting, then final `agent: summary`
