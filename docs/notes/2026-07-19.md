## BCI (brainwave) channel compatibility

Question: can HLP stay compatible if human input later arrives via EEG/BCI?
Answer: **yes, by design** — spec appendix C (0.3 draft) already converged
BCI semantics; executed `docs/plans/2026-07-19-bci-channel-compat.md` to
prove it with a reference slice.

### What was added

- `examples/hlp_bci_channel_demo.py` (`uv run loops-hlp-bci-demo`):
  `SyntheticBCIDecoder` (channel-plane only) emits
  `ControlSignal(source_kind="bci")` values; demonstrates
  1. soft BCI stream → `merge_soft_control_signals` → one `task.amend`
     (D1: state unchanged; audit provenance carries `source_kind="bci"`),
  2. high-confidence hard affirm + low-risk checkpoint → resolve succeeds,
  3. same + high-risk checkpoint without second factor → `UNAUTHORIZED`
     (D3 fail-closed),
  4. same + `second_factor_present=True` → resolve succeeds;
  plus an example channel-side risk policy (`checkpoint_is_high_risk`:
  option risk flags + prompt keywords).
- 3 offline tests in `tests/test_hlp_realtime.py` (demo evidence, risk
  policy, decoder contract). `pyproject.toml` script `loops-hlp-bci-demo`.
- README BCI compatibility section, `docs/architecture/hlp.md` channel
  note, CHANGELOG entry.

### Verification

- `pytest tests/` → 246 passed, 2 skipped; ruff/mypy clean.
- `uv run loops-hlp-bci-demo` → all four paths produce the expected
  evidence JSON (D3 denial included).

### Boundary kept (C.10)
