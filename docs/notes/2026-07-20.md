### W1 — native structured output for the projection contract

The weakest link was prompt-disciplined JSON echoes (live failures: claude
`status:"acknowledged"`, pi missing correlation echo). Codex and Claude Code
both have native structured-output switches, now wired in protocol mode:

- `HLP_RESULT_SCHEMA` (`_parsing.py`): closed envelope `run_id`,
  `correlation_id`, `status(ok|error)`, `summary`, `error`.
  Live iteration with codex strict mode taught: `additionalProperties: false`
  required at every object level, and `required` must list every property —
  so no optional `hlp` field; human-loop events keep flowing through
  intermediate stream text (existing extraction handles it).
- `ClaudeCodeHarnessAdapter` / `ClaudeCodeCLIAdapter`: `--json-schema`
  (inline). `CodexHarnessAdapter` / `CodexCLIAdapter`: `--output-schema`
  (schema written once per process to a system temp file, `atexit` cleanup).
- Chat mode never gets the flag (free-form replies); custom commands are
  never rewritten; Kimi/Pi have no such flag (docstring-noted).

Live verification (this machine, both via `HLPClient.delegate`):

- claude: result envelope carries `structured_output` with the exact
  correlation echo; **parse fix**: extraction now digs `structured_output`
  (it was missing from the dig keys — would have silently dropped the
  validated envelope).
- codex: `item.completed` agent_message text is exactly the schema object;
  correlation + status deterministic.

New `tests/test_hlp_projection_robustness.py` (14 tests): schema wiring per
adapter/mode/custom-command, closed-schema invariant, and wire variance per
CLI (markdown fences, prose, CRLF, unicode, duplicate embedded hlp event →
projects once, missing correlation tolerated, malformed line fail-fast,
`structured_output` preference, codex `item.completed` shape).
