## Runtime adapter / model switching in the TUI

User request: switch adapter and model without restarting.

- `build_client(..., store=)` — clients can be rebuilt over the SHARED
  HumanLoopStore, so task history survives a switch.
- `TUIController(adapter_builder=...)` — host injects a factory;
  `/adapter <name>` rebuilds the client and, when a task is active,
  `ownership.transfer` hands it to the new adapter (fresh run, fork if the
  target CLI supports it). `/model <name>` rebuilds with the new model on
  live adapters (records only on fake). `set_preference` gained `adapter`.
- 3 offline tests (rebuild + handoff + shared store identity, validation,
  model rebuild vs fake).

## TUI /adapter 深度修复（用户直播抓出的三个问题）

1. **进度标签停留在启动 adapter**：REPL 每轮从 `sessions.resume(...).adapter`
   取标签（原来用 `args.adapter` 固定值）。
2. **跨 CLI 切换的 handoff 是静默 no-op（根因）**：`_switch_adapter` 把任务交给
   `self.agent_id`（"agent_tui"），而 TUI 任务的 assignee 本来就是
   "agent_tui"——`ownership_transfer` 的 `to != assignee` 条件不满足，adapter
   handoff 从未触发：没有新 run、没有会话绑定，后续 steer 全靠
   `_require_run` 的宽容分支一次性调用，上下文与 fork 全丢（pi 会话文件证实
   每次调用都是新会话）。修复：交给 `agent_{target}`（assignee 必不同，真触发），
   并给 `/handoff` 加"已分配给该 agent"的防呆。
3. **跨 CLI 上下文简报**：无共享会话时（跨 CLI），切换后经现有 steer 通道把
   最近 transcript 简报注入新会话（HOST NOTE 强指令格式），结果消息明示
   "no shared session history"。同 CLI（如仅换 model）走原生会话 fork，不注入。
