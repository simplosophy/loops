# HLP TUI Channel Plan

| | |
|---|---|
| **日期** | 2026-07-07 |
| **状态** | 设计已批准，待实现计划 |
| **关联** | HLP host/channel boundary, Claude Code TUI compatibility, Codex CLI compatibility |

## 背景

HLP 当前是 agent harness 的 human-interaction control plane。它拥有 Task、
Checkpoint、Artifact、Review、Ledger、Audit、adapter boundary 和 human inbox
语义，但明确不拥有 UI/channel 渲染、模型调用、工具执行、sandbox 或 agent loop。

Claude Code 和 Codex CLI 的主流 TUI 能力并不只是一个 prompt 输入框，而是一组
围绕长会话 coding-agent 工作流的交互面：prompt composer、transcript、状态栏、
slash commands、权限档位、审批对话、diff/review、session 管理、文件提及、
shell 输入和审计可见性。HLP 已经具备人类决策和验收语义，因此 TUI 应作为
HLP host/channel 层补足这些交互面，而不是把 `loops.hlp` 改造成新的 harness。

## 目标

- 新增一个基于 HLP 的 TUI channel，提供 `loops-hlp-tui` console command。
- 覆盖 Claude Code / Codex CLI 等 agent harness TUI 的常用 90% 交互面：
  prompt composer、transcript、status line、slash commands、permissions、
  inbox approval、artifact review、audit replay、session lifecycle、`@file`
  mention parsing、`!shell` input capture 和 diff/review workflow。
- TUI 通过 `HLPClient`、`HLPHost`、`human_inbox()` 和现有 adapters 驱动协议对象。
- 运行时执行继续交给 `CodexCLIAdapter`、`ClaudeCodeCLIAdapter`、
  `CodexHarnessAdapter`、`ProcessAgentAdapter` 或其他 harness adapter。
- 保持 `loops.hlp` SDK-only、harness-agnostic、channel-agnostic 的架构纪律。
- 默认测试离线稳定，使用 fake/injected adapter 验证 TUI 到 HLP 的闭环。

## 非目标

- 不在 TUI 中实现模型 provider、tool runtime、MCP runtime、agent planning loop、
  memory/RAG、sandbox enforcement 或 OS 级安全边界。
- 不把 `loops.hlp` 反向依赖 `loops.tui`。
- 不尝试逐像素复刻 Claude Code 或 Codex 的专有界面。
- 不让 fake adapter 成为 quickstart 或生产默认 runtime；fake 只用于离线测试和 demo。
- 首版不实现完整 curses/fullscreen 交互；先实现可测试的 line-oriented TUI core，
  后续可在同一 controller/render 边界上替换为 richer terminal backend。

## 架构

新增 `loops/tui/` 包。该包是 HLP 的 host/channel layer：

```text
Human user
  -> loops.tui: composer, slash commands, sessions, transcript, rendering
  -> loops.hlp.HLPClient / HLPHost
  -> AgentAdapter / HarnessAdapter
  -> Codex, Claude Code, Kimi, custom process, framework runtime
```

依赖方向必须保持单向：

```text
loops.tui -> loops.hlp
loops.hlp -X-> loops.tui
```

`loops.tui` 可以读取并展示 HLP 对象、调用 HLP SDK facade、选择 adapter、投影
harness event。`loops.hlp` 不知道 TUI 的存在。

## 组件边界

| 文件 | 责任 |
|---|---|
| `loops/tui/__init__.py` | TUI public API re-export |
| `loops/tui/app.py` | line-oriented app shell、主循环、stdin/stdout 边界 |
| `loops/tui/controller.py` | 将 TUI intent 转成 `HLPClient` 操作 |
| `loops/tui/commands.py` | slash command parser、命令定义和 dispatch metadata |
| `loops/tui/session.py` | session/thread metadata、transcript、fork/resume/archive/delete |
| `loops/tui/render.py` | deterministic text rendering：status、inbox、audit、review、help |
| `loops/tui/compat.py` | Claude Code / Codex 兼容命令目录和覆盖率声明 |
| `examples/hlp_tui_demo.py` | 离线 demo，使用 injected/fake adapters |
| `tests/test_hlp_tui.py` | TUI parser、controller、render、session 和 demo 测试 |

首版实现保持依赖极简，优先使用 Python 标准库。若后续需要 full-screen backend，
可以在不改变 controller/session/commands 的前提下添加 optional backend。

## 用户交互模型

### Prompt Composer

- 普通文本输入创建或延续当前 HLP Task。
- 如果没有 active task，composer 创建 Task、delegate 给选定 adapter 并 start。
- 如果已有 active task，composer 默认追加为 steering amendment，映射为
  `client.amend(..., intent="clarify")`。
- `@path` 被解析为文件 mention token，首版只作为 prompt/context metadata 记录，
  不直接读取文件或绕过 harness 权限。
- `!command` 被解析为 shell-input transcript item，首版不执行命令；需要执行时交给
  harness 或后续受控 shell adapter。

### Transcript

Transcript 是 TUI channel 的本地会话视图，记录：

- user prompt / slash command
- HLP task/run/checkpoint/artifact/review/audit summaries
- adapter/harness projection result
- error event

Transcript 不替代 HLP audit。HLP audit 仍是协议事实来源；transcript 是 UI 可读历史。

### Status Line

状态栏展示：

- session id
- active task id 和 task state
- adapter name
- autonomy/permission mode
- pending inbox count
- current working directory

## Slash Command Compatibility

首版 command catalog 分为直接实现、HLP 映射、兼容响应三类。

| 命令 | 首版行为 | 类型 |
|---|---|---|
| `/help` | 展示命令目录和兼容说明 | 直接实现 |
| `/new` | 创建新 TUI session，不复用 active task | 直接实现 |
| `/clear` | 清空当前可见 transcript，保留 HLP state | 直接实现 |
| `/resume` | 从本地 session store 选择并恢复 session | 直接实现 |
| `/fork` | 复制 transcript/session metadata，生成新 session id | 直接实现 |
| `/archive` | 标记当前 session archived 并退出 | 直接实现 |
| `/delete` | 删除本地 session 记录，需要确认 | 直接实现 |
| `/permissions` | 切换 autonomy/grants preset | HLP 映射 |
| `/inbox` | 展示 `client.human_inbox(principal)` | HLP 映射 |
| `/approve` | resolve 当前 pending checkpoint 为 approve | HLP 映射 |
| `/reject` | resolve 当前 pending checkpoint 为 reject | HLP 映射 |
| `/choose` | resolve choice checkpoint | HLP 映射 |
| `/input` | resolve input checkpoint | HLP 映射 |
| `/amend` | `client.amend()` 追加 steering | HLP 映射 |
| `/interrupt` | `client.interrupt()` 人发起阻塞点 | HLP 映射 |
| `/review` | 对当前 artifact 提交 review 或启动 harness review task | HLP 映射 |
| `/audit` | `client.replay_audit(task_id)` | HLP 映射 |
| `/diff` | 展示 git diff summary；首版可通过 injected provider 测试 | 直接实现 |
| `/model` | 记录 preferred model metadata；实际模型选择由 adapter/harness 解释 | 兼容响应 |
| `/mcp` | 展示兼容说明：MCP 属于 harness/tool runtime | 兼容响应 |
| `/statusline` | 展示和切换 status fields | 直接实现 |
| `/theme` | 记录 theme name；line-oriented 首版只影响文本标签 | 直接实现 |
| `/vim` | 记录 composer mode metadata；不实现完整 Vim editor | 兼容响应 |
| `/compact` | 对 transcript 做本地摘要记录；不改 HLP audit | 兼容响应 |

命令解析必须 deterministic：未知命令返回 usage error，不触发 HLP mutation。

## Permission Mapping

Codex 的 approval modes 和 Claude Code 的 permission modes 映射到 HLP
`Constraints.autonomy` 与 append-only `PermissionGrant`：

| TUI mode | HLP autonomy | 语义 |
|---|---|---|
| `auto` | `autonomous` | 允许 harness 在当前工作边界内自主推进；越界仍由 harness checkpoint |
| `plan` | `plan_then_implement` | 首次执行前要求 plan review |
| `confirm` | `confirm_each_action` | 倾向每个 proposed action 走 checkpoint |
| `read-only` | `read_only` | TUI 不主动请求修改；实际 enforcement 由 harness/sandbox |

TUI 只表达权限意图和人类批准记录；OS sandbox 和 tool gating 必须由 harness 或宿主环境执行。

## 数据流

### 新任务

```text
composer input
  -> TUIController.submit_prompt()
  -> HLPClient.create_task()
  -> HLPClient.delegate()
  -> HLPClient.start()
  -> transcript records task/run summary
```

### Harness 需要人类决策

```text
adapter emits human-facing event
  -> HLPClient.project_harness_events(run_id)
  -> Checkpoint
  -> HLPClient.human_inbox(principal)
  -> TUI renders inbox item
  -> /approve, /reject, /choose, /input
  -> HLPClient.resolve_checkpoint()
  -> adapter.resume()
```

### Artifact Review

```text
harness artifact event or explicit commit
  -> HLPClient.commit_artifact()
  -> task enters review_ready
  -> TUI /inbox shows review item
  -> /review approved|changes|rejected
  -> HLPClient.submit_review()
```

### Human Steering

```text
user prompt on active task or /amend
  -> HLPClient.amend()
  -> adapter.steer()
  -> steering_log append-only
```

## 错误处理

- Adapter failure：显示 `adapter.operation` 和 details；HLP fail-before-commit 保证状态不假成功。
- Invalid command：显示 usage，不修改 session/HLP state。
- Invalid state transition：显示 `ProtocolError.code`，保留当前 task。
- Session persistence failure：fail fast，提示具体 path 和操作。
- Harness event correlation mismatch：显示 conflict，拒绝投影。
- Review/checkpoint action missing target：提示运行 `/inbox` 或指定 id。

## 测试策略

- Parser tests：slash command、quoted args、`@file`、`!shell`、unknown command。
- Controller tests：prompt-to-create/delegate/start、prompt-to-amend、approve/reject/choose/input、
  interrupt、review、audit。
- Render snapshot tests：help、status line、inbox、audit、artifact review、error。
- Session tests：new/resume/fork/archive/delete、transcript append、clear visible transcript。
- Compatibility catalog tests：确保声明的 command coverage 不低于首版目标。
- Demo test：`examples/hlp_tui_demo.py` 使用 injected fake/harness adapter 完成 create、
  checkpoint、approve、artifact、review、audit 全流程。
- Regression tests：`uv run pytest tests/test_hlp_tui.py -q`，并保持现有
  `uv run pytest tests/test_hlp_sdk.py -q` 和 `uv run pytest tests/test_hlp_protocol.py -q`
  通过。

## 首版明确延期项

- Fullscreen backend 选型延后；首版先保证 line-oriented TUI core 可测试、可组合。
- `!shell` 是否由 TUI 直接执行延后；首版只捕获和展示，避免绕过 harness/sandbox。
- `/model` 是否转成 adapter-specific input metadata 延后；首版记录 preference。
- `/mcp` 只展示 harness-owned capability，不在 TUI 启动 MCP server。

## 设计结论

采用独立 `loops.tui` host/channel 层是当前最小且正交的方案。它使 Loops 获得
Claude Code / Codex 类 TUI 的主要人机交互体验，同时不破坏 HLP 作为协议 SDK 的
边界：HLP 仍只统一人类委派、审批、转向、验收和审计语义，实际 agent execution
继续由外部 harness 拥有。
